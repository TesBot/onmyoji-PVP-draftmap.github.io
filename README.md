# 翻牌上卡导引图

《阴阳师》斗技「禅吞」体系的翻牌 / 上卡决策导引图，做成**配置驱动**的单页应用：
页面内容全部来自 `config.json`，改配置就能改页面，不用改代码。

支持多方案切换 / 拖动排序、方案级导出导入、节点可视化编辑（含式神头像选择器）、汇合复用
（同一套我方方案被多条敌方起手路径指向）、暗色主题，可直接作为 GitHub Pages 静态站点发布。

## 方案存哪里：示例 vs 自建

页面上的方案分两类，标签上带徽标区分：

| 徽标 | 含义 | 会不会丢 |
| --- | --- | --- |
| **示例** | 写在 `config.json`（并内嵌进 `index.html`）里的方案，随页面一起发布，无法删除 | **不会丢**。清缓存、换设备、换浏览器都还在 |
| **自建** | 你在页面上新建 / 复制 / 导入的方案，只存在浏览器 localStorage | **会丢**。清理浏览器数据、换设备就没了 |

只要存在「自建」方案，方案栏下会出现一行短提醒，点名是哪几个、提示导出备份：

> ⚠ 自建导图「XX」仅存本机浏览器，清缓存即丢失，建议导出 JSON 备份。

### 方案的日常操作（都在顶部方案栏右侧）

| 按钮 | 作用 |
| --- | --- |
| `＋ 新建` | 新建空白方案 |
| `复制` | 复制当前选中的方案（副本为自建） |
| `导出` | 弹出导出面板，三种产物可选（见下节） |
| `导入` | 选择 JSON 文件导入方案；接受 单个方案 / 方案数组 / `{schemes:[…]}` 三种写法，导入后一律是自建方案，id 冲突自动改号 |

标签本身支持**拖动排序**（顺序保存在浏览器本地），双击标签可重命名。

### 导出：三种产物

点「导出」会弹出一个选择面板，导出的是**当前选中的那一个方案**：

| 产物 | 说明 |
| --- | --- |
| **JSON（可再导入）** | 只存这一个方案的数据。不含 `builtin` / `rev`，可以拿「导入」塞回页面，也能直接粘进 `config.json` 的 `schemes` 数组。式神配置表跟着一起走。 |
| **单 HTML（只读·头像固化）** | 一个文件带全部用到的头像，双击就能打开，**不依赖旁边任何目录**。浏览器打开后只保留查看能力：单击收起 / 展开、翻阅式神配置表。 |
| **PNG 图片** | 按当前视图导出成一张图，**下方直接拼接这个方案的式神配置表**，方便贴图分享 |

**关于单 HTML 只读版**：它和当前页面共用同一套渲染 / 布局代码，所以折叠展开、暗色切换、式神配置抽屉的表现完全一致；
区别只是「改不了」——没有右侧编辑面板，双击节点不再弹出任何东西，方案栏的新建 / 复制 / 导出 / 导入按钮撤掉，
配置表单元格不能双击编辑、也没有删除列，而且不会往浏览器里写任何东西。

**关于 PNG**：不截图，而是用现成的布局数据重画一次，所以**导出的是逻辑坐标而非屏幕像素**——
窗口多小都导得出来，文字是矢量的清晰度；节点位置、字号、头像大小、阵营配色全部跟着当前主题走。
导出时会先把头像转成 data URL 再画，避免画布被污染。

**头像靠什么固化**：导出要取头像的二进制，而用 `file://` 直接双击打开时，`fetch` / `XHR` 会被同源策略拦住。
所以页面在点开导出面板时会按需加载一份构建时生成的头像包 `assets/avatars-inline.js`
（276 张压成 80px webp，约 1.5 MB；用 `<script src>` 加载，**脚本标签不受这个限制**）。
平时不加载、不拖慢打开速度。这份包缺失时会退化成逐张 `fetch`（http 环境下可用），
再不行才会退化成占位框——面板底部的提示会提前告诉你本方案有几个头像已经就绪。

```bash
node src/build_avpack.js     # 重新生成头像包（改了头像库之后跑，从自包含预览版里抽取）
```

### 画布上的操作

| 手势 | 效果 |
| --- | --- |
| **单击**带子框的节点 | 收起 / 展开它的子框（父节点右上角出现子节点数量徽标） |
| **单击**最末端的节点 | 无子框可收，不做任何事 |
| **双击**任意节点 | 打开右侧编辑面板（描述 / 阵营 / 手数 / 式神 / 御魂 / 备注） |
| 单击画布空白处 | 关闭编辑面板、清掉选中态 |
| 滚轮 / 拖动 / 键盘方向键 | 缩放 / 平移导图 |
| 鼠标停在节点上 | 提示当前节点支持的两个手势 |

**面板内部怎么点都不会把面板关掉**：点头像、点「已选式神」标签、点「引用来源」的 ✕ 这类操作都会即时
重建面板内容，判定「这一下是不是点在空白处」必须在元素被重建**之前**做完，否则会被误判成点空白、面板
自己跑掉。这个顺序由 `src/check_cfg.js` 的 Q 段盯住，真实点击由 `src/shot.js` 的 3b / 4b / 4c 三步盯住。

编辑面板标题的格式是 **`编辑节点：<节点 ID>` + 一条浅色的描述**，ID 做成了可点的小徽标
（**点一下即复制**，复用 / 引用 / 排查数据时直接拿去用）；悬停 ID 也有同样提示。

单击与双击的区分靠一个可配置的延迟 `ui.clickFoldDelay`（默认 160ms）：
单击先等一小会儿再折叠，如果这期间来了第二下就判定为双击、取消折叠，改成打开编辑面板。
所以两个手势互不干扰。顶栏只剩三个按钮：`适应窗口` / `只看体系` / `暗色`（按钮由 `ui.buttons` 驱动，可以自行增删）。

**原地编辑不会搬动镜头**：编辑节点点「应用」、「＋ 新增子卡」、「复用已有」、删节点、改页面配置，
画布的缩放与位置都保持不变（`rebuild(true)`）；
只有**换了另一张图**的动作才会重新适配视图——切换 / 新建 / 复制 / 导入方案，以及「只看体系」和「适应窗口」。

**「只看体系」是逐级展开的起点**：它会把所有一级以下的框**连同各自的子孙一起收起**（而不是只收一层），
所以之后点开任何一个框都只会露出它的直接下一层，可以按需一级级往下走；
框右上角的数字徽标就是它收着多少个子孙，随时点「适应窗口」回到全貌。

### 拖节点：自由布局（偏移量）

按住任意节点框就能拖到别处。自动布局**照常计算**，只是在最后把这个节点上的 `dx / dy` 叠加上去——
所以新增子节点仍然自动落位，不用手摆每一个；连线、「适应窗口」、导出（JSON / 单 HTML / PNG）
读的都是最终坐标，全部自动跟上。

- 偏移量存在节点的 `dx / dy` 字段里（必须是有限数字，写坏了会被校验丢掉，绝不进布局变 NaN）；
- 位移阈值 3px：手抖仍然算单击 / 双击，拖完那一下 click 会被吃掉，不会顺手折叠或弹出面板；
- 开关：`ui.interaction.nodeDrag`（关掉则位置永远由自动布局说了算）；
- 想放回自动位置：右键菜单里的「**复位位置**」。

### 节点右键菜单

在节点框上点右键，弹出：**编辑** / **添加子节点** / **添加同级节点** / **复位位置** / **删除节点**。

实现上不赌浏览器一定派发 `contextmenu`：**按下右键（mousedown button=2）就弹**，随后浏览器补派的
`contextmenu` 用时间戳（600ms）吃掉、只拦原生菜单。菜单挂在 `<body>` 上用 `position:fixed` 定位
（放 `#stage` 里会被它的 `overflow:hidden` 裁掉，缩放平移还会把坐标系带歪）。

两种情况「添加同级节点」会**灰掉并写明原因**（插到哪儿说不清，不猜）：
**根节点没有父级**，以及**这个节点被多处复用**（父级不止一个）——后者请先到源头那一处添加。
删除项在有多处引用时会写成「删除整个节点」，确认框里会列出受影响的引用处。

### 汇合节点（多路径走到同一处）

「复用已有」会让同一个节点被多条路径引用。默认渲染（`layout.sharedNodeMode: "merge"`）：

- 共享节点**全图只画一个框**，不再复制副本；
- 多出来的那条路画成一条**虚线箭头**指回那唯一的框（虚线 + 箭头 = 复用汇合，区别于普通父子实线）；
- 框的左上角带 **⤵N 徽标**，N = 有几条路径汇进来；
- 汇合点的图内文字默认**截断到 10 字 + …**（`layout.sharedTitleMax` 可调，0 = 不截断），悬停看全文；
- 编辑面板里会标明「N 处引用同步」——改一处，所有引用处同步。

汇合虚线走的是**绕行折线**，并且画在**节点之上**（`#wiresTop` 那一层）、底下垫一条半透明底衬：
被复用的框常常在别的深度、甚至在左边，直接拉曲线会从沿途一堆框身上压过去，
看着就像连到了错误的框。现在它会先出到列间空档竖着走，再从目标框的上（或下）边缘扎进去。
导出 PNG 时也按同样的上下层顺序画，成图和页面一致。

**「解除复用」只在源头那一处做**——也就是复用别人的那个框：

- 发起复用的框（汇合虚线的起点）上有「**本框复用了**」，逐条列出它复用出去的节点，
  行尾 **✕** 只断开**本框 → 它**这一条，那个节点本身和其它引用都保留；
- **被复用的框上不给解除入口**：那里的「引用来源」只是说明「被哪些分支引用」，
  没有 ✕、也没有「解除复用」按钮。同一件事两头都能点的话，很容易点错一侧、断错那条；
- 真要删掉这个节点，在被复用的框上点「**删除整个节点**」，确认框会列出所有受影响的引用处；
  只想去掉其中某一处，就到那个框上去解除。

老行为（每个引用处画一个折叠的「↻ 复用」副本）仍在，把 `layout.sharedNodeMode` 改回 `"collapse"` 即可。

### 式神配置表（每方案一张）

上卡前每个式神要配好御魂，所以每个方案都可以带一张配置表：
**序号 / 式神 / 指标 / 御魂套装 / 246号位 / 其他要求**。

- 平时**完全不占地方**——点方案栏右侧的「式神配置」才会从导图下方浮出一张抽屉卡，再点就收走；
- 按钮上带行数徽标（`式神配置 · 3`），一眼看出这个方案录了几条；
- 式神列支持简称（输「炎魔」自动带出阎魔头像），单元格**双击**编辑、回车保存、行尾 ✕ 删除；
- 「＋ 添加一行」会自动打开抽屉并让新行直接进入编辑态；
- 这张表跟着方案一起**导出 / 导入**，各方案互不影响。
- **示例方案预填了两行范例**（阎魔 / 鬼吞），既是参考也是演示——嫌碍事就选中后行尾 ✕ 删掉；
  改动会体现在 `rev` 里，下次打开页面时会提示「示例导图已随页面更新」。

### 想把自建方案固化成示例方案

1. 选中该方案，点方案栏「导出」，得到一份单方案 JSON；
2. 把它粘进项目根目录 `config.json` 的 `schemes` 数组，并加上 `"builtin": true`；
3. 重新构建页面：

   ```bash
   python src/build_cfg.py
   ```

4. 提交推送。构建时 `build_config.py` 会自动补上内容版本号 `rev`，下次打开时它就是「示例」方案了。

作者更新示例方案后 `rev` 变化，页面会自动把新版同步给所有老访客（本地若有改动会被覆盖并提示一次）。

### 页面配置与方案解耦

顶栏只有三个按钮：**适应窗口 / 只看体系 / 暗色**（由 `ui.buttons` 配置驱动）。
「编辑」「页面设置」两个入口**已彻底删除**（连同页面设置面板的实现一起删了）：
页面配置改由 `config.json` 维护，改完重跑 `python src/build_cfg.py` 即可生效。

导出单 HTML 时取的「页面配置」（`pageConfigOf()`：标题 / 布局 / 样式 / 别名 / 头像索引）
**不包含任何方案数据**——方案的增删、切换、排序、导出、导入全部在方案栏完成。

#### 视图设置（layout）会跟着版本走

`layout` 管的是「怎么显示」（间距、缩放、汇合节点怎么画），**没有编辑入口**，
浏览器里存的那份只是上次存盘时的快照。

这就有个坑：老版本页面往 `localStorage` 存过 `sharedNodeMode: "collapse"`，
而 `file://` 下所有本地页面共用同一个存储 origin，键名还一样（`chantun.config.v1`）——
于是打开新版时，旧偏好会被读回来、把新版默认的 `merge` 压回去，
表现就是「汇合节点还是多画一个框」。

所以 `layout` 带一个 `rev` 版本号：本地那份没 `rev` 或比发布版旧时，
**整体换成发布版**并在侧栏告警一次；`rev` 相同则尊重访客这份（想回退老的 `collapse` 模式，
直接在 `config.json` 里改并保持 `rev` 不低于发布版即可）。

**顶栏按钮（`ui.buttons`）也一律以发布版为准**：老页面把「编辑 / 页面设置」这两个按钮写进过
`localStorage`，页面配置面板删掉之后本地再也没有合法来源改它，但那份旧快照会一直把顶栏压回 5 个按钮
——表现就是「明明已经删了，我打开还是有」。现在刷新时会直接用发布版那份并告警一次。

顺带修掉一处同源的老问题：`validate()` 里 `deepMerge` 顶层是浅拷贝，
`raw` 里没提到的字段会直接共用内嵌默认值的对象引用，
往 `CFG.layout` 上写一次就会把「默认值」本身改脏，之后每次校验拿到的都不再干净。
现在合并结果整份深拷贝。

## 本地开发

### 预览

`index.html` 用同步 XHR 读取同目录的 `config.json`，建议经由 HTTP 打开：

```bash
python -m http.server 8123
# 浏览器打开 http://127.0.0.1:8123/index.html
```

直接双击（`file://`）也能用，页面会自动退回内嵌配置，**并且自动把 `assets/avatars-inline.js`
这份头像包挂上再渲染一次**——个别浏览器在 `file://` 下读不到同目录的图片子资源（节点头像会全变成
`?` 占位框），而 `<script src>` 不受这条限制，所以走动态脚本这条路（`fetch` / XHR 在 `file://` 会被拦）。

> 想彻底不依赖旁边任何文件，直接用 `dist/单文件-自带头像.html`（头像已内联成 dataURL，双击即开）。

### 改数据 / 重新生成

```bash
python src/build_config.py   # 重新生成 config.json（改了 nodes.json 或头像库后跑）
python src/build_cfg.py      # 把 config.json 注入模板，产出 index.html
```

### 自包含预览版（看不到头像时用这个）

`index.html` 的头像走相对路径 `assets/shishen/avatars/...`，必须**整个目录一起**通过 HTTP 或
`file://` 打开才看得到。某些预览面板 / 只代理单个 HTML 的环境会拿不到这些子资源，
此时节点上的头像会全部退化成 `?` 占位框。

需要单文件分发（发别人、贴到别处预览）时生成一个内嵌版。**优先用这条，不需要浏览器**：

```bash
node src/build_singlefile.js
# -> dist/单文件-自带头像.html（约 1.6 MB，双击即开，可编辑，不依赖 assets/ 与 config.json）
```

它复用已入库的 `assets/avatars-inline.js`。头像库更新过、需要重新压制 dataURL 时才走浏览器那条路：

```bash
# 前置：python -m http.server 8123 与无头 Chrome（--remote-debugging-port=9223）已启动
node src/build_standalone.js   # -> dist/standalone-preview.html（276 张压成 80px webp）
node src/build_avpack.js       # -> 从上面那份抽出 assets/avatars-inline.js
```

内嵌版通过 `window.__AV_INLINE__` 提供头像，页面优先取它、取不到再回退相对路径，
所以 `index.html` 本身不用改，发布到 GitHub Pages 时也不受影响。

### 更新式神头像

新式神上线后，跑一次官网增量下载脚本（会同时重建清单与索引页）：

```bash
python assets/shishen/更新脚本.py
```

它会：拉取官方式神录 → 下载到 `avatars/<稀有度>/`（联动另存 `collab/`、呱太另存 `gua/`）
→ 重写 `式神清单.csv` → **重建 `索引.html`**（样式沿用现有文件，只重新生成卡片，避免手改路径出错）。

头像更新完，还要让页面认到新头像索引：

```bash
python src/build_config.py   # 重新扫描 avatars/ 生成 avatarIndex
python src/build_cfg.py      # 重新注入 index.html
```

> 注意：呱太的文件名本身就带「呱」（如 `大天狗呱.png`），与 `gua/` 目录名是两回事。
> 索引页由脚本生成，不要把文件名里的字当成目录名去替换。

### 校验

```bash
node src/check_cfg.js
```

跑布局正确性（无 NaN / 无重叠 / 无孤立方块 / 无幽灵节点 / 连线数一致）、200 轮随机折叠压力测试、
非法配置兜底、简称展开（含头像库 276 个名字的全量回环）、汇合复用、多方案、配置读写、
示例同步（rev）、方案拖动排序与导出导入、视图设置版本同步（旧偏好不反压新版）等断言。
`CHECK_HTML=<变体文件> node src/check_cfg.js` 可以把校验指向一份故意改坏的页面副本。

单文件产物（双击打开的那份）另有一道成品校验：

```bash
node src/verify_singlefile.js          # 默认校验 dist/单文件-自带头像.html
node src/verify_singlefile.js <路径>    # 换一份产物
```

看的是：内嵌 `layout.rev` / 默认是 `merge`、带版本同步与深拷贝、276 张头像都在、
`script` 闭合 3 个（多一个就会截断主脚本）、没被误锁成只读产物。

浏览器交互冒烟（需要本机 Chrome）：

```bash
node src/shot.js
```

服务（8123）和无头 Chrome（9223）都由脚本自己拉起，不用预先开终端；
外面已经在跑的话就直接复用，跑完自动退出。

反向验证（可选，只在怀疑某个回归测试「其实抓不到 bug」时跑）：把已经修好过的那几个坑逐个还原成坏代码，
确认对应的断言真的会 FAIL，跑完自动清掉临时文件。A 例需要无头 Chrome，连不上时会跳过、只跑 Node 例：

```bash
node src/neg_check.js
```

## 配置项速览

`config.json` 顶层 8 个区块：

| 区块 | 作用 |
| --- | --- |
| `meta` | 页面标题（同时驱动页头与浏览器标签名） |
| `ui` | 顶栏按钮（标签 / 动作 / 是否显示）、交互开关、单击转折叠的延迟 `clickFoldDelay` |
| `layout` | 间距、列模式（按层级深度）、折叠阈值、缩放范围、共享节点渲染方式等 |
| `style` | 字号、节点尺寸、头像尺寸、各阵营配色、明暗两套主题变量 |
| `assets` | 头像目录、头像索引（名字 → 相对路径）、占位说明 |
| `aliases` | 简称 → 正式式神名（编辑器里输「炎魔」能找到「阎魔」） |
| `yuhun` | 御魂 / 术语词表（只做文字标签，不当式神） |
| `schemes` | 方案列表：`builtin` 示例标记、`rev` 内容版本、节点表 `nodes` |
| `activeScheme` | 当前选中的方案 id（导出页面配置时会剔除它，由方案栏管理） |

> `aliases` 只覆盖**有简称的那几十个式神**。`shishen` 里写全名不需要它在 `aliases` 里出现，
> 直接写头像索引 `assets.avatarIndex` 里的名字即可（编辑器里点头像也是这样写进去的）。

节点模型：

```json
{ "id": "n2", "title": "敌方：禅吞内战", "camp": "enemy", "hand": 2,
  "shishen": ["禅心云外镜", "鬼王酒吞童子"], "yuhun": [], "note": "",
  "children": ["n3", "n4"] }
```

`children` 里存的是 **id 引用**，所以同一个节点可以被多条路径指向（汇合复用）——
这正是「敌方前几手顺序不同、后面走到同一套我方方案」的建模方式。

## 术语口径

- **「带 XX」后面跟的是阴阳师（主角），不是式神**：神乐、源赖光、晴明、八百比丘尼、藤原道长。
  式神图鉴里没有他们的头像，目前以占位框呈现。
- **神乐 ≠ 联动式神「神乐&定春」**，前者是主角。
- 御魂（薙魂、青女房、共潜、蚌精、狂骨、骰子鬼、出世螺、奉海图等）只作文字标签，不当式神处理。
